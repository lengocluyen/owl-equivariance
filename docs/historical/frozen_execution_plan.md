# Frozen model and inference envelope; dataset pre-freeze plan

**Protocol:** `owleq-jws-2026-07-v1`  
**Freeze date:** 2026-07-25  
**State:** model/budget locally validated; primary dataset capacity screening incomplete;
no paid inference has been authorized or executed

An open-weight `gpt-oss-120b` arm served by LM Studio is supported but is not frozen until
the server preflight records the exact LM Studio model id, GGUF/model-file SHA-256,
quantization, context length and loaded state; the smoke response records runtime metadata.
It should replace `gpt-5.6-luna` if the
primary matrix must remain at exactly six models; otherwise report it as a seventh
open-weight reproducibility anchor.

The machine-readable authority is `configs/publication_experiment.yaml`. If this document
and the YAML differ, stop the run and resolve the discrepancy by issuing a new protocol id.

## Six primary model endpoints

| Provider | Capable tier | Efficient tier | Primary reasoning setting |
|---|---|---|---|
| OpenAI | `gpt-5.6-terra` | `gpt-5.6-luna` | `medium` |
| Anthropic | `claude-opus-4-8` | `claude-sonnet-5` | adaptive, effort `medium` |
| Google | `gemini-3.6-flash` | `gemini-3.5-flash-lite` | thinking level `medium` |

All calls use the identical `structured_proof` prompt, structured JSON output, no tools,
one primary response, and a 1,024-token output ceiling. Provider-returned response ids,
served model/version, usage, latency, finish reason, and thinking-token counts are retained.
The primary matrix uses one response per item. A frozen 20% stratified subset receives two
additional responses, for three responses total, and is never expanded after results appear.

Preview endpoints and moving `latest` aliases are excluded. The Google GA ids do not expose
a dated slug, so the run records `model_version` from every response and fails the provenance
audit if it changes within a run.

## Dataset panel

CL and PO are discovery-only. They may calibrate prompt length, power, and cost, but they
must not be used to tune the generator after confirmatory outcomes exist.

The held-out TBox candidate panel is:

| Source | Role | Screened state |
|---|---|---|
| GO | large OBO style | consistent OWL 2 DL; frozen EL extraction required |
| ENVO | OBO style with 44 individuals | consistent OWL 2 DL; frozen EL extraction required |
| W3C SSN | compact non-OBO, meaningful IRIs | rejected as primary: EL fragment yields 0 items |
| ETSI SAREF Core 4.1.1 | compact non-OBO, meaningful IRIs | external probe only: 16 balanced items |
| Schema.org 30.0 | large non-OBO, meaningful IRIs | replacement candidate; capacity build pending |

The planned ABox arm uses two reproducible corpora:

1. LUBM-1 generated by UBA 1.7 with `-index 0 -seed 0`, joined to Univ-Bench.
2. The official SAREF 4.1.1 examples, joined to the pinned SAREF Core ontology.

This distinction matters: LUBM and the SAREF examples are ABox corpora, not two additional
independent ontology engineering styles. Claims and tables must say so explicitly.

Each admitted confirmatory material source must contribute 200 balanced base items before
paid inference. Sources that fail this pre-outcome capacity rule are external probes or are
replaced before the dataset freeze. After the dataset freeze, do not replace rejected items
or sources. The full lexical panel is
`C0,C1,C2,C3,C4,C4S2,C5,C6,C7,C8,C9`.

## Costed call budget

The budget envelope reserves 1,200 base items x 11 conditions = 13,200 primary prompts per model.
Two extra repeats on a 20% subset add 5,280 prompts per model. Therefore:

- 18,480 calls per model;
- 110,880 calls across six models;
- 46.2 million conservatively budgeted input tokens per model (2,000-token observed mean
  with a 25% safety factor);
- 3.55 million expected output tokens per model at a 192-token planning mean;
- 18.92 million output tokens per model at the absolute 1,024-token ceiling.

At the standard prices frozen in the YAML, the expected cost is about **$866**. The
all-responses-at-ceiling estimate is about **$1,958**. The global hard cap is **$2,000**.
Provider invoices remain authoritative; prompt caching or batch discounts are not assumed.

Recalculate immediately before execution:

```powershell
.\.venv\Scripts\python.exe -m owl_equivariance.cli budget `
  --manifest configs\publication_experiment.yaml --stage confirmatory

.\.venv\Scripts\python.exe -m owl_equivariance.cli budget `
  --manifest configs\publication_experiment.yaml --stage confirmatory --ceiling
```

## Execution order and stopping gates

1. Finish capacity screening and freeze six sources that each meet their preregistered quota.
2. Build and certify all held-out EL fragments and ABox joins.
3. Validate complete 11-member orbits, balanced labels/context sizes, mapping bijections,
   prompt leakage, and model-specific token matching.
4. Run the deterministic baselines and the power simulation.
5. Freeze dataset hashes and the 20% repeat subset.
6. Run four complete orbits per discovery ontology on all six endpoints as a smoke test.
7. Inspect parsing, refusals, served versions, token usage, and cost. Any prompt or schema
   change creates a new protocol id and repeats the smoke test.
8. Execute one provider/model at a time with `--resume`, raw response retention, the prices
   from the YAML, and a per-model cap copied from the ceiling budget table.
9. Symbolically validate supports before statistical analysis.

Example for one already-certified dataset:

```powershell
.\.venv\Scripts\python.exe -m owl_equivariance.cli infer `
  --dataset data\certified\cl\benchmark.jsonl `
  --model openai:gpt-5.6-terra `
  --style structured_proof `
  --reasoning-effort medium `
  --max-output-tokens 1024 `
  --limit-orbits 4 `
  --input-price-per-mtok 2.50 `
  --output-price-per-mtok 15.00 `
  --max-cost-usd 400 `
  --resume `
  --progress 50 `
  --output data\predictions\cl.gpt-5.6-terra.jsonl
```

Do not start paid inference until `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, and
`GOOGLE_API_KEY` are available in the execution environment and the $2,000 cap is explicitly
approved. Keys must never be written to the repository or command history.

For LM Studio, first expose the server to this client and set its URL without a trailing
endpoint path, for example:

```powershell
$env:LM_STUDIO_BASE_URL = "http://SERVER-IP:1234/v1"
.\.venv\Scripts\python.exe -m owl_equivariance.cli lmstudio-preflight `
  --model "EXACT-ID-FROM-LM-STUDIO" `
  --weights-sha256 "SHA256-COMPUTED-ON-THE-SERVER" `
  --output reports\lmstudio-gpt-oss-120b.preflight.json
```

Compute the hash on the LM Studio server itself (`Get-FileHash <model.gguf> -Algorithm
SHA256` on Windows or `sha256sum <model.gguf>` on Linux). Do not expose an unauthenticated
LM Studio port to the public Internet; use a private network, VPN, or SSH tunnel.

Only after that succeeds, run a four-orbit smoke test:

```powershell
.\.venv\Scripts\python.exe -m owl_equivariance.cli infer `
  --dataset data\certified\cl\benchmark.jsonl `
  --model "lmstudio:EXACT-ID-FROM-LM-STUDIO" `
  --reasoning-effort medium --max-output-tokens 1024 `
  --limit-orbits 4 --progress 4 `
  --output data\predictions\cl.gpt-oss-120b.smoke.jsonl
```

### Six-model LM Studio server panel

On a Linux server that already has all six catalog models installed, the complete
orchestrator is `scripts/run_lmstudio_publication.sh`. It loads one model at a time,
records the exact local artifact hash when its path is exposed by LM Studio, runs the
symbolic support validator, evaluates each dataset, and uses resumable prediction files.
The safe default is:

```bash
bash scripts/run_lmstudio_publication.sh smoke
```

After every model passes the smoke gate:

```bash
RUN_ID=owleq-discovery-v1 \
  bash scripts/run_lmstudio_publication.sh discovery
```

Confirmatory mode is intentionally unavailable with the current CL/PO discovery data. Once
six certified datasets each contain at least 200 complete 11-condition orbits, invoke it
with the explicit dataset list and approval gate shown in the script header. Confirmatory
mode also freezes a deterministic, stratified 20% orbit subset and obtains repeat indices
1 and 2 in addition to the primary repeat-0 response.
